# 餐道行业文案示例库

版本：v1.0  
日期：2026-08-15

## 1. 页面标题

反面：

```text
开启餐饮数字化增长新体验
```

问题：

- 没有业务对象；
- 没有餐道产品能力；
- 可替换给任何餐饮 SaaS。

正面：

```text
把多平台外賣訂單、門店接單與配送狀態接成一條營運鏈路
```

为什么正确：

- 包含订单、门店、配送三个业务对象；
- 能承接 OMS / DMS / iDMS；
- 与餐道业务流程直接相关。

适用页面和角色：

- Home / Platform；
- 决策者、总部运营、IT。

## 2. 指标卡

反面：

```text
平台稳定性 99.99%
```

问题：

- 未在当前资料中定义；
- 容易成为 SLA 承诺。

正面：

```text
DMS 平台可用性
99.95% over
来源：PPT Slide 131
```

为什么正确：

- 数值来自 PPT；
- 指标对象是 DMS；
- 保留来源和口径。

## 3. 订单列表字段

反面：

```text
订单 / 用户 / 状态 / 操作
```

问题：

- 状态不够具体；
- 缺少渠道、门店、异常和下一步操作；
- 不适合多平台订单后台。

正面：

```text
訂單編號 / 渠道 / 門店 / 訂單狀態 / 配送狀態 / 異常類型 / 更新時間 / 下一步操作
```

为什么正确：

- 贴合 OMS 订单处理；
- 支持门店、配送、异常和操作闭环。

## 4. 异常提醒

反面：

```text
系统异常，请稍后再试。
```

问题：

- 没有业务对象；
- 没有触发条件；
- 没有下一步操作。

正面：

```text
門店 A 有 3 張外賣訂單接單超時超過 5 分鐘，可能影響出餐與配送。請通知門店接單或改由營運人員處理。
```

为什么正确：

- 包含门店、订单、超时条件、影响和下一步。

## 5. 空状态

反面：

```text
暂无数据
```

问题：

- 没有说明当前对象；
- 没有说明下一步。

正面：

```text
目前沒有待處理異常訂單。若門店接單超時、退款未處理或配送狀態中斷，系統會在此顯示。
```

为什么正确：

- 明确对象是异常订单；
- 说明何时会出现数据。

## 6. 表单说明

反面：

```text
填写信息，我们将尽快联系你。
```

问题：

- 没有解释字段用途；
- 对 Demo 分流没有帮助。

正面：

```text
請留下品牌、地區、門店規模、目前使用的外賣平台與 POS 系統。我們會根據你的營運場景安排 OMS、DMS、iDMS 或數據對賬演示。
```

为什么正确：

- 字段直接服务演示分流；
- 连接产品模块。

## 7. 操作确认

反面：

```text
是否继续？
```

问题：

- 没有对象；
- 没有风险；
- 操作后果不明确。

正面：

```text
確定要將這批配送中訂單轉派第三方配送？轉派後，系統會更新配送狀態並保留原騎手派單記錄。
```

为什么正确：

- 明确对象、动作、状态变化和记录保留。

## 8. 图表标题

反面：

```text
运营趋势
```

问题：

- 对象不明；
- 没有维度和用途。

正面：

```text
各平台訂單量與門店接單狀態
```

为什么正确：

- 同时包含平台订单和门店接单状态；

## 9. 原型阶段删减

反面修改：

```text
原文：比對平台訂單與餐道 OMS 訂單，識別金額錯誤、狀態錯誤和漏單。
原型：查看對賬結果。
```

问题：

- 删除平台订单、OMS 订单、金额错误、状态错误、漏单这些关键业务对象。

正确处理：

```text
保留原文并调整布局；如溢出，报告溢出位置和可用空间，不自行缩短。
```

## 10. 泛化价值表述

反面：

```text
用数据驱动业务增长，打造高效协同平台。
```

正面：

```text
把平台訂單、OMS 訂單和對賬文件放在同一流程比對，協助財務識別金額差異、狀態差異和漏單。
```

为什么正确：

- 业务对象、流程和异常都明确；
- 适合「財務對賬」能力和财务角色；不在繁體中文可见页面直接展示 `Finance Center`。

## 11. 产品名大小写

反面：

```text
IDMS / DMS / SAAS Platform
```

问题：

- `iDMS` 的首字母 `i` 被错误改成大写；
- `SaaS` 被错误改成全大写；
- 这不是普通排版问题，会破坏产品名识别性。

正面：

```text
iDMS / DMS / SaaS Platform
```

为什么正确：

- 保留 `iDMS` 的小写 `i` 和大写 `DMS`；
- 保留 `SaaS` 的标准写法；
- 符合 `glossary.yaml` 的大小写敏感术语。

适用页面和角色：

- Platform / Integrations / About / Demo；
- IT、配送主管、采购方、销售。

原型样式反面：

```css
.block-kicker {
  text-transform: uppercase;
}
```

问题：

- 会把 `iDMS` 视觉上显示为 `IDMS`；
- 即使源码文本正确，用户看到的产品名仍然错误。

正确处理：

```css
.block-kicker {
  text-transform: none;
}
```

或者通过字重、字号、色彩和间距强化层级，不改变文字大小写。

## 0. 品牌显示规则

- 中文、繁體中文、项目叙述和官网默认显示品牌名统一使用「餐道」。

- 官网前台不再将 `Candao` 作为中文 / 繁體中文默认品牌显示。
- PPT 原文中的 `Finance Center` 可作为证据来源名称保留；进入中文 / 繁體中文官网、Figma、Stitch、React 或截图式界面时，默认改写为「财务对账 / 財務對賬」或更具体的「平台订单与 OMS 订单对账」。

## 1. 产品类型

餐道国际官网面向餐饮与零售 O2O 业务，核心产品类型不是泛 SaaS，也不是普通企业官网，而是：

- 餐饮与零售 O2O 营运 SaaS；
- 订单、餐单、门店、配送、会员、财务和数据的连接型平台；
- 面向总部、门店、配送和 IT 团队的营运中枢；
- 支持 OMS / COMS / SOMS、CDBI、财务对账、DMS、iDMS、AMS / Connector、Mobile Ordering、QR / H5 / Web ordering 等能力的产品与服务体系。
- 旧官网产品体系当前视为完整；如有欠缺，可能是支付能力，后续按菜单目录补充并提出缺口。

## 2. 目标用户

- 国际或香港市场的餐饮集团、连锁餐饮品牌、零售鲜食品牌、Pizza / Fast Food 品牌、咖啡品牌、火锅 / 中餐 / 甜品连锁。
- 正在处理多平台外卖、自有点餐、门店接单、配送履约、会员运营、报表分析和财务对账复杂度的品牌。
- 需要验证餐道是否能接入现有 POS、KDS、支付、CRM、ERP、第三方配送、外卖平台和自有点餐入口的采购方。

## 3. 用户角色

| 角色 | 关注点 | 文案应回答 |
|---|---|---|
| 品牌管理层 / 决策者 | 规模、可信、投入产出、长期合作 | 餐道是否有足够行业经验、客户案例和可公开数据 |
| 总部运营 | 多平台订单、餐单、门店、异常、报表 | 如何减少多后台切换、漏单、重复维护和门店不可见 |
| 门店经理 / 店员 | 接单、打印、制作、售罄、异常提醒 | 当前要处理什么订单，状态是什么，下一步怎么做 |
| IT / 集成团队 | API、系统类型、数据流、权限、安全 | 接入对象、字段口径、系统边界和异常处理路径 |
| 配送主管 | 派单、骑手、第三方溢出、监控、短信通知 | DMS / iDMS 如何管理骑手、订单状态和履约异常 |
| 财务 / 数据团队 | 对账、漏单、金额差异、报表、GMV | 数据从哪里来，如何比对，异常如何定位 |
| 市场 / 会员团队 | 会员等级、权益、营销活动、私域入口 | 会员和营销如何与订单、餐单、渠道回到同一链路 |

| 销售 / 售前 | 相似案例、演示入口、需求分流 | 用哪个场景承接客户问题，下一步演示什么 |

## 4. 核心业务流程

1. 多渠道订单进入  
   外卖平台、自有 H5 / Web / APP / QR、Call Center 等订单进入餐道 OMS / COMS。

2. 订单标准化与门店处理  
   订单进入统一后台，按门店、渠道、状态、异常、制作和配送状态进行处理。

3. 餐单与库存同步  
   Menu Center 维护餐单、库存、售罄、区域菜单、平台差异和模板，减少多平台重复维护。

4. 门店营运管理  
   总部维护门店信息、营业时间、接单状态、配送范围、门店异常和订单超时提醒。

5. 配送履约  
   iDMS 聚合配送资源，DMS 管理自有骑手、智能派单、人工派单、第三方溢出、骑手 APP、SMS 通知和监控报表。

6. 数据资产与财务对账  
   CDBI / Data Asset / 财务对账处理报表、数据看板、订单分析、对账、金额错误、状态错误和漏单识别。

7. 客户服务与持续营运  
   Merchant Service / Operation and Helpdesk services 承接导入、运营支持、异常处理和持续优化。

## 5. 关键业务对象

- 品牌、门店、区域、渠道、外卖平台、自有点餐入口；
- 订单、订单状态、订单异常、退款、取消、投诉、催单；
- 餐单、菜品、SKU、库存、售罄、餐单模板、区域菜单；
- POS、KDS、打印设置、小票模板、后厨单、收银单；
- 顾客、会员、会员等级、会员权益、优惠券、营销活动；
- 配送单、骑手、骑手角色、派单规则、配送区域、第三方物流、SMS；
- 报表、看板、对账单、GMV、订单量、复购率、取消率、运营效率；
- API、字段、权限、系统状态、异常状态、数据流。

## 7. 主要状态和异常

订单状态：

- 待接单、已接单、制作中、配送中、已完成、已取消、退款中、异常。

门店状态：

- 营业中、暂停接单、休息中、门店关闭、营业时间待同步、配送范围待更新。

配送状态：

- 待派单、已派单、骑手已接单、到店、取餐、配送中、已送达、转第三方、配送异常、超时。

常见异常：

- 漏单、重复订单、接单超时、配送超时、退款未处理、取消未同步、金额不一致、状态不一致、缺少配送坐标、门店状态异常、库存售罄未同步、餐单更新失败、对账差异。

- 未提供资料的客户、价格、合同、 SLA、未确认合作伙伴状态；
- 未经确认的第三方品牌 Logo 视觉使用。

## 9. 已确认事实与合理假设

### 已确认事实

- 旧官网和 PPT 是当前最高权威资料。
- 用户确认本轮提供资料均为最新版。
- 用户确认 PPT 中数据完全准确，授权完全展示。
- 餐道是面向餐饮与零售 O2O 的 SaaS / Data / Delivery / QA 服务体系。
- Candao Information Technology Co., Ltd. 成立于 2014 年，总部广州，有北京、上海、香港分支和成都运营中心。
- 餐道有 20 年餐饮系统研发与餐饮外送业务实战经验。
- 旧官网产品体系完整；如后续发现欠缺内容，优先检查支付能力并按菜单目录补充。
- 产品名可以沿用 PPT 或旧官网。
- PPT 中可使用的客户和案例包括 Pizza-Box、JIA Group、Jardine Group / KFC / Pizza Hut / PHD、McDonald's / Yoshinoya 线索，以及甜品、火锅、中餐、咖啡、鲜食零售等行业案例。
- 品牌名、Logo、项目截图、案例数字、客户引用语均可用于高保真和正式官网。
- 用户提供的 SVG Logo 资产已保存为 `assets/logo/candao-blue-logo.svg`；Home Hero 下方可使用该 SVG 配合 Hero 风格形成 Logo 带。

- 首要服务对象为销售转化对象和品牌决策者。

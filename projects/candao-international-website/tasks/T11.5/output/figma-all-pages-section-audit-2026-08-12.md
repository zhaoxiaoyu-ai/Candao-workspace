## 1. 本轮补充目的

上一份报告已经判断了全站主线、目录覆盖和主要风险，但粒度仍偏页面级。这一版补充到每个页面的每个可见板块，逐一回答：

| 审查问题 | 判断口径 |
|---|---|
| 为什么存在？ | 这个板块是否对应用户认知、业务场景、产品能力、接入验证、信任证明或联系转化。 |
| 是否辅助流程？ | 它是否推动用户进入下一步，而不是只在页面内堆信息。 |
| 是否重复或冲突？ | 它是否与其他页面或同页其他板块讲同一件事，或违反 IA / Locale / 事实边界。 |
| 是否有案例支撑？ | 它是否需要真实案例、PPT 来源、客户授权、数据或认证支撑。 |
| 如何优化？ | 给出保留、合并、改写、降权、删除或移到其他页面的建议。 |

## 2. 全站推荐叙事主线

当前最顺的官网主线应固定为：

```text
首頁
建立第一认知：Candao 是餐饮营运平台，不是单点工具。

解決方案
让用户从自己的业务场景进入，确认“我的问题被理解”。

平台
展示 Candao 如何通过产品能力、UI 状态和工作流解决问题。

整合能力
验证能否接入用户已有的外送、POS、支付、CRM、物流和内部系统。

客戶案例
在授权前用谨慎模板，在授权后用真实案例证明落地。

資源
降低评估、导入、使用、媒体和查询疑虑。

關於 Candao
说明公司是谁、如何服务、是否可信、如何联系。

預約產品演示
按意图收集需求，并把销售、合作、支持查询分流给合适团队。
```

这条线必须避免一个问题：不要让每一页都重新解释“Candao 是统一平台”。每页只回答它自己的问题。

## 3. 全站重复与冲突地图

| 重复 / 冲突点 | 出现位置 | 当前影响 | 全站处理原则 |
|---|---|---|---|
| “一个平台连接订单、门店、配送、数据”反复出现 | Home、Solutions、Platform | 用户会觉得每页都在重新开始，而不是递进 | Home 只讲一句定位；Solutions 讲业务场景；Platform 展开能力和 UI。 |
| “接单到数据回馈”的工作流重复 | Home Product Showcase、Platform Workflow Strip | 首页和平台页节奏撞车 | 首页做 5 秒概览；Platform 做完整产品流程、状态变化和数据流。 |
| 能力卡到处出现 | Home、Solutions、Platform、Customers | 页面边界模糊，Solutions / Customers 像 Platform 分身 | 能力卡墙只属于 Platform；其他页面只放少量“推荐能力”或反向链接。 |
| 未确认数字像真实事实 | Home、Solutions、Customers | 会破坏可信度和法律/销售口径 | 未确认前全部删除、改为状态词，或标注“示例结构”。 |
| 未授权 Logo | Home Hero | 与 Candao 客户和生态无关，直接伤害信任 | 全部移除，改成类别标签或授权 Logo。 |
| 两套导航叠加 | Solutions、Integrations、Customers 等 | 旧 IA 和新 IA 同时存在 | 保留一套统一导航，删除旧 TopNav。 |
| `资源` / `資源`、`關於餐道` / `關於 Candao` 混用 | 多页导航和页脚 | 违反繁體中文单 Locale 规范 | 统一为 `資源`、`關於 Candao`。 |
| 联系入口过多但边界不清 | Resources、About、Demo | 用户不知道该去 Demo、支援中心还是联系公司 | Resources 管支持和资料查询；About 管公司联系；Demo 管产品/销售/合作/支持分流。 |

## 14. 总结

当前 Figma 页面不是“页面缺很多”，而是“每个页面都想把自己讲完整”，导致全站横向重复。真正要做的是给每页分配单一任务：

```text
Home 只负责开场和导流。
Solutions 只负责业务场景。
Platform 只负责产品能力和 UI 工作流。
Integrations 只负责接入验证。
Customers 只负责可信证明。
Resources 只负责疑问和支持入口。
About 只负责企业可信和服务方式。
Demo 只负责转化分流。
```

只要按这个分工修，用户看完整站后会自然形成完整认知：餐道是谁、解决什么问题、产品如何工作、能否接入现有系统、有没有可信证明、下一步该怎么联系。

## 风格判断

新版首页的核心不是“蓝色 SaaS 模板”，而是“餐饮营运场景 + 企业级产品工作台 + 已授权规模证明”的组合。它解决之前高保真泛化的问题：第一屏先让访客看到餐饮场景、品牌可信度和产品界面，再用平台中枢说明餐道如何连接订单、菜单、门店、配送与数据。

## 可复用页面节奏

1. Hero 使用暗色真实场景或授权产品场景，中心化主叙事，蓝色只强调关键转折。
2. Hero 下方可让产品截图舞台跨出标准画布，形成官网级视觉冲击，但不得使用假产品截图。
3. 深色平台段负责解释系统连接关系，不应做成普通三列卖点卡。
4. 白底案例段负责承接可信证明，案例卡必须围绕实名客户、场景、使用产品和改善结果。
5. 深色规模数据带只放 PPT Slide 11 授权指标，不放自创百分比。
6. Final CTA 使用白底和真实运营媒介拼贴，回到销售转化动作。

## Typography 决议

MCP 输出中部分中文文本使用 Inter 并带负字距，这是 Figma-to-code 参考代码的视觉结果；项目正式 token 仍保持：

- 繁體中文：`Noto Sans TC` / `PingFang TC` / `Microsoft JhengHei`
- 英文、数字、技术词：`Inter`
- `letter-spacing: 0`
- 不使用 `text-transform`

理由：项目已锁定产品名大小写敏感规则，负字距和大小写转换都可能影响 `iDMS`、`SaaS`、`AMS / Connector` 等识别性术语。

## 不可照搬项

- Platform Overview 中 `-80%`、`-95%`、`+60%`、`100%` 没有进入当前授权指标表，不得用于正式官网事实。
- Customer Cards 中的简体词如“意式餐厅”“全链路”“配送履约、门店订单...”必须改回繁體中文和 domain-copy 标准术语。
- Customer Cards 的彩色小方块是模拟 Logo，不得当作正式客户 Logo。
- 平台徽标、产品截图、视频封面、公司照片、证书图均需真实素材或授权素材；缺失时只保留结构位。

## 对剩余页面的约束

- Solutions：使用“场景叙事 + 滚动分段 + 对应产品截图位”，避免变成产品清单。
- Integrations：使用“系统网络 + API 数据流 + 接入对象状态”，避免泛泛说无缝集成。
- Customers：沿用左引导 + 右案例卡，但每张卡必须体现客户、场景、产品覆盖、前后对比数据或已确认结果。
- Resources：用内容路径和支持入口，不做营销卡片堆叠。
- About：使用公司时间线、服务体系和地点/交付网络，避免“从外送经验长出来”式表达。
- Demo：使用多步骤表单 + 动态需求摘要，形成销售转化动作。

## QA 要求

后续 Stitch / Figma / 前端输出前必须检查：

- 导航包含：首页、解決方案、平台、整合能力、客戶案例、資源、關於餐道、預約產品演示。
- 页面正文为繁體中文单一 Locale；Header 可有 `繁中 / EN`。
- 中文 / 繁體中文默认显示「餐道」。
- `iDMS`、`SaaS`、`AMS / Connector` 大小写保持不变。
- 不出现内部词、PPT 页码、OLD 编号、placeholder、missing、假 Logo、未授权数字、假产品截图。
- 每页都要有清晰 CTA，但 CTA 类型按页面任务变化，不强行同一文案。

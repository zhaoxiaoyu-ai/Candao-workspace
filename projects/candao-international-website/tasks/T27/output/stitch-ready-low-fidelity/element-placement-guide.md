# 餐道国际官网 Stitch-ready 元素放置指南

版本：2026-08-19  
适用包：`stitch-ready-low-fidelity`  
用途：给 Stitch 生成高保真 screen 前使用，说明每个页面模块应放置什么元素。本文不是官网访客可见文案，不应直接渲染到页面中。

## 全局元素规则

- 页面 HTML 是内容与结构参考；本指南补充元素类型、素材边界和禁止替代方式。
- 所有页面保持繁體中文单一 Locale，Header 只保留 `繁中 / EN` 语言切换。
- 中文、繁體中文品牌显示使用「餐道」；产品名保留 `iDMS`、`SaaS`、`AMS / Connector` 等标准大小写。
- 可使用真实素材：餐道 SVG Logo、授权指标、实名客户名称、已授权案例数字。
- 必须等待真实素材或清理后才能使用：产品截图、产品视频、客户 Logo、客户现场照片、公司照片、证书图片、客户引用语原图。
- 可用抽象表达：业务拓扑图、流程图、低保真系统关系图、指标布局、资源路由、表单分流摘要、时间轴。
- 不得生成：未授权客户 Logo、虚构产品截图、虚构仪表盘数据、未确认 SLA、未确认合作方状态、通用 SaaS 功能卡片墙。
- 如果缺素材，保留清晰的媒体区域和元素意图，不用模型重画真实产品 UI。

## 首頁

| 模块 | 放置元素 | 元素说明 | 缺素材处理 | 禁止替代 |
| --- | --- | --- | --- | --- |
| Header | 餐道 SVG Logo、一级导航、语言切换、预约演示按钮 | Logo 使用授权 SVG；导航保持 8 页路径 | 无 | 不用文字 `Candao` 代替「餐道」 |
| Hero | 左文案 + 右产品舞台 | 产品舞台展示订单、门店、配送、对账四类状态行；可作为真实截图容器 | 如无真实截图，用中性状态面板，不出现虚构订单编号、客户名或金额 | 不生成假仪表盘、不放通用办公插画 |
| 营运中枢 | 中心节点拓扑图 | 中心为「餐道營運中樞」，外围为外卖平台、自有点餐、POS / KDS、CRM / 会员、配送、支付 / ERP、财务数据 | 用抽象节点和连线即可 | 不混成单纯产品目录或功能清单 |
| 能力探索器 | 左侧 rail + 右侧截图舞台 + 要点列表 + CTA | 五项为渠道聚合、营运承接、配送履约、数据对账、生态接入 | 截图位保持媒体区域，内容以业务对象和状态说明支撑 | 不做六宫格通用功能卡 |
| 服务规模 | 六个授权指标卡 | 使用 5000+、500M+、400+、200K+、4.5B+、30% up | 指标必须原样保留，不新增数值 | 不替换为“强大数据能力” |
| 案例摘要 | 主案例卡 + 次案例摘要 | 默认可用 Pizza-Box、JIA Group；显示客户名称、合作范围、下一步 | 客户 Logo 缺失时用客户名称文字 | 不生成未授权 Logo 或匿名模板 |
| 底部 CTA | 深色转化带 | 主按钮到 Demo，次按钮到 Platform | 无 | 不用“了解更多”单独承接 |

## 解決方案

| 模块 | 放置元素 | 元素说明 | 缺素材处理 | 禁止替代 |
| --- | --- | --- | --- | --- |
| Hero | 场景地图或汇聚流程图 | 展示外卖平台、自有点餐、门店、配送、对账从分散到可追踪 | 可用抽象流程，不需要真实截图 | 不做产品卡 Hero |
| 常见营运问题 | 三张问题卡 | 多平台订单履约、门店与餐单营运、配送营运与对账 | 使用简洁线性图标 | 不写泛化价值词 |
| 场景导览 | 六项场景 rail + 右侧详情面板 | 每个场景要显示问题、承接产品、业务对象、下一步 | 没有场景照片时用流程图 | 不把 Solutions 写成 Platform 产品说明书 |
| 场景详情 | 问题-能力-结果链路 | 当前场景切换时链路同步变化 | 可使用三段式 Stepper | 不新增未确认指标 |
| 案例入口 | 对应场景案例小卡 | 只做导流，不展开完整案例 | 无客户图时用客户名和业态 | 不生成未授权客户 Logo |

## 给 Stitch 的使用顺序

1. 先打开对应页面 HTML，确认页面顺序和访客可见文案。
2. 再读取 `element-placement-map.json` 中同一页面的 `modules`。
3. 按 `required_elements` 布局模块，不因视觉好看删除业务对象、状态、条件、数据口径和下一步操作。
4. 遇到 `real_asset_required` 但素材缺失时，使用 `fallback`，不得生成看似真实的产品截图、客户 Logo、视频封面或证书图。
5. 生成结果必须保留页面故事路径和所有受保护术语。

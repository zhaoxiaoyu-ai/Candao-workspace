# SOLUTIONS Prompt

## 页面目标

让访客从业务场景进入，而不是从产品列表进入。Solutions 负责说明问题、场景、角色压力和推荐能力，再导向 Platform 或案例。

## 访客可见内容

标题：從多平台訂單、門店、配送到對賬，梳理餐飲 O2O 營運場景。  
说明：解決方案頁按品牌遇到的問題組織內容，不把產品逐項平鋪。使用者先確認場景，再進入平台能力、案例或演示。

## 模块顺序

1. S01 Hero：多平台订单、门店、配送、对账的场景入口。
2. S02 三类方案总入口：订单履约、对账分析、自有点餐会员。
3. S03 六项场景 Sticky Explorer。
4. S04 问题 → 能力 → 结果流程。
5. S05 对应案例。
6. S06 CTA。

## 模块呈现方式

- S01：场景入口 Hero，右侧展示订单、门店、配送和对账汇聚的流程动画位。
- S02：三类方案总入口，使用 Tabs 或大分段控件，不做等权卡片墙。
- S03：桌面端 Sticky scenario storytelling，移动端改 Accordion。
- S04：问题 → 能力 → 结果状态链，随场景切换。
- S05：只展示对应案例入口，不重复 Customers 完整内容。
- S06：场景化 CTA，文案跟随当前场景。

## 交互状态

- 默认：显示多平台外卖订单场景。
- Hover：预览对应产品能力。
- Click：锁定场景，流程、截图位和 CTA 同步变化。
- Scroll：一个场景一个段落，不连续堆卡片。
- Mobile：场景改 Accordion。

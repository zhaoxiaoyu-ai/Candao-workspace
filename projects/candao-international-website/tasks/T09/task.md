# Task T09: 设计原型验证 Agent

## Goal

基于 T08《Website UX Specification》进行官网关键页面设计原型验证。

T09 不重复做 UX 规划，不重写官网 Copy，不重新解释战略定位。T09 的重点是验证页面线框、页面节奏、关键交互、UI Demo 脚本和移动端降级方式是否可进入 T10 视觉设计。

## Output

《Website Prototype Validation》

## 输出语言

简体中文。

页面名、组件名、交互名和原型关键词可保留英文，例如 `Wireframe`、`Prototype Flow`、`Product UI Demo`、`Scroll-triggered Stepper`。

## 前置输入

必须读取：

1. `tasks/T07/output/final-website-copy-v1.0-2026-08-03.md`
2. `tasks/T08/output/website-ux-specification-2026-08-03.md`
3. `tasks/T08/output/t08-v1.1-design-execution-supplement-note-2026-08-03.md`

优先依据：

- T08 的 Design Component Framework；
- T08 的 Cross Page User Journey；
- T08 的 Visual Priority Definition；
- T08 的 Figma Structure Recommendation。

## Requirements

- 输出页面线框验证，不输出最终视觉稿。
- 必须验证核心页面：
  - Home；
  - Products / Platform；
  - Order Management；
  - Delivery Management；
  - Integrations Overview；
  - Contact / Book a Demo。
- 可轻量验证：
  - Solutions Overview；
  - Restaurant Chains；
  - Cases / Customers；
  - Company / About。
- 每个重点页面必须包含：
  - Wireframe Structure；
  - Page Rhythm；
  - Key Interaction；
  - Motion Validation；
  - Responsive Validation；
  - Prototype Flow；
  - Risk / Open Questions。
- 必须验证跨页面路径：
  - Home → Restaurant Chains → Platform → Case → Demo；
  - Home → Integrations → Request Integration；
  - Home → Platform → Order Management / Delivery Management → Demo。
- 不设计完整视觉系统，不定义最终颜色、字体和摄影风格；这些留给 T10。
- 不把未确认客户、Logo、认证、数据、集成状态或 SLA 放入原型事实。

## Acceptance

- 文档能支撑 T10 视觉设计 Agent 与 T13 最终整合。
- 输出语言保持简体中文。
- 已明确哪些页面需要进入 Figma 高保真，哪些页面只需模板化。
- 已明确 Home、Platform、Order、Delivery 的关键原型验证重点。

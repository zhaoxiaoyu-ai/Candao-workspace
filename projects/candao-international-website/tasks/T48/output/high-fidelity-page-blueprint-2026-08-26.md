# 接入评估中心高保真页面蓝图

日期：2026-08-26  
页面：`接入評估中心 / Desktop 1440 / TC`  
用途：将 `整合能力`、`客戶案例`、`資源` 三者组合成一个可直接进入高保真设计的页面输入。

## 页面定位

`接入評估中心` 不是把三页拼在一起，而是给销售转化对象、品牌决策者、IT 和运营团队一个评估入口：

`现有系统能否接入 -> 需要准备哪些资料 -> 是否有相似案例 -> 接下来该看资源、提交支持还是预约演示`

## 叙事结构

1. Hero：用餐饮运营场景 + 接入评估工作台，在首屏直接说明“系统、案例、资源”如何合并。
2. System Fit Workbench：让 IT 和运营按系统类型查看资料对象、同步状态、异常回传和产品关系。
3. Case Proof Board：用实名案例、授权规模数据和业态结果证明餐道处理过相似场景。
4. Resource Router：把评估、导入、日常运营、技术查询分成可操作资源路径。
5. Decision Matrix：把问题、系统、相似案例和资源下一步放到同一判断界面。
6. Demo Summary：将选择结果带入产品演示需求摘要。

## 模块规格

### 1. Header

布局：
- 绝对定位在 Hero 顶部，内容宽度 1200px。
- 左侧餐道 Logo，中部一级导航，右侧 `繁中 / EN` 与 `預約產品演示`。

高保真要求：
- Header 透明或深色玻璃底，不能像普通后台导航。
- 导航必须包含：首页、解決方案、平台、整合能力、客戶案例、資源、關於餐道。

### 2. Hero Product Stage

页面任务：
- 让访客在 5 秒内理解：这是一页用于判断接入可行性、查案例和找资源的评估页面。

布局：
- 左侧标题与 CTA。
- 右侧或下方跨画布产品舞台，表现 `接入評估工作台`。
- 背景使用真实餐饮运营场景，叠加深色遮罩。

必须出现的产品 UI：
- 当前问题：多平台订单、餐单更新、门店接单、配送与对账差异。
- 系统来源：外賣平台、自建點餐、POS / KDS、CRM / 會員、支付 / ERP、配送 API。
- 处理层：AMS / Connector。
- 使用层：OMS、Menu Center、DMS / iDMS、財務對賬、CDBI。
- 下一步：提交接入评估或预约相似场景演示。

不可出现：
- `Finance Center`
- 假平台接入状态
- “所有系统均可接入”
- “无缝 / 無縫”

### 3. System Fit Workbench

页面任务：
- 承接原 `整合能力` 页面，但不能只展示集成类别。必须表现输入、校验、回传和使用。

布局：
- 左侧垂直系统类型 rail。
- 中部系统网络或字段映射表。
- 右侧状态摘要和异常回传。
- 下方三块能力承接：资料来源、校验同步、营运使用。

组件：
- Segmented rail：外賣平台、自建點餐入口、POS / KDS、CRM / 會員、支付 / ERP、配送 API。
- Data object chips：訂單、菜單、門店、庫存、會員、支付、配送、對賬。
- Status rows：待映射、同步中、异常回传、可用于 OMS / CDBI。
- CTA：`提交接入評估`。

### 4. Case Proof Board

页面任务：
- 承接原 `客戶案例` 页面。重点不是放客户名，而是说明相似场景、产品范围、导入前后变化和可参考结果。

布局：
- 白底 editorial section。
- 左侧说明“从不同餐饮业态看落地方式”。
- 右侧案例卡或横向案例板。
- 中段或下段加入授权规模数据带。

案例结构：
- `Pizza-Box`：9 年合作，OMS + 自有点餐，第三方配送整合、自有配送、营销工具、经营分析与客户服务。
- `JIA Group`：多品牌、多门店营运，数据与服务回流。
- `Jardine Group`：DMS / iDMS 配送履约。

业态结果：
- 甜品连锁、火锅连锁、中餐连锁、咖啡品牌、鲜食零售、配送密集品牌。
- 指标只使用 `domain-copy/glossary.yaml` 已授权值。

### 5. Resource Router

页面任务：
- 承接原 `資源` 页面。资源不是营销卡片，而是采购、IT、运营、门店、配送、财务各角色的下一步。

布局：
- 左侧阶段 rail：评估中、导入中、日常营运、技术查询。
- 中部资源详情：接入准备、常见问题、支持查询、案例资源。
- 右侧 Demo readiness panel：已选择的问题、现有系统、推荐演示模块。

资源类别：
- 接入准备清单
- 营运 FAQ
- 案例资源
- 支援中心
- 媒体与公司资料
- 产品演示分流

### 6. Decision Matrix

页面任务：
- 将三类内容压缩成实际判断表，帮助用户不用先读完整站就能找到下一步。

布局：
- 深色区，类似产品内决策台。
- 四列：目前问题、接入 / 产品关系、相似案例、资源下一步。
- 每行要有标签、状态、CTA 或路由。

默认行：
- 多平台订单、餐单更新、门店接单与漏单风险。
- 配送超时、派单规则、第三方配送状态回传。
- 平台订单与 OMS 订单金额、状态、漏单差异。

### 7. Demo Summary CTA

页面任务：
- 把前面选择过的问题、系统和案例变成销售演示摘要。

布局：
- 白底 media mosaic CTA。
- 左侧转化文案和按钮。
- 右侧摘要表单：意图、推荐模块、业态与地區、现有系统、主要问题、下一步。

CTA：
- 主按钮：`預約產品演示`
- 次按钮：`查看資源入口`

## 内容覆盖策略

高保真版本仍需 100% 内容可追溯，但覆盖口径改为：

| 层级 | 处理方式 | 示例 |
| --- | --- | --- |
| P0 默认可见 | 页面核心判断必须直接显示 | H1、系统来源、AMS / Connector、OMS、客户案例、资源阶段、Demo CTA |
| P1 模块可见 | 卡片、工作台、表格和列表承载 | 接入对象、资料对象、状态、案例产品范围、FAQ |
| P2 交互 / 详情可见 | Tab、Accordion、资源详情、表单摘要 | 各业态指标、媒体资料、支援分流、演示推荐模块 |

不再把 224 个文本片段作为同级正文塞入页面，但必须在合同中映射到页面模块，且 QA 能检查是否有内容丢失。

## 高保真失败判定

出现以下任一情况即失败：

- 页面看起来像三页内容拼接，而不是一个评估中心。
- 首屏没有产品 UI 或接入评估工作台。
- 只有卡片和文字，没有系统网络、状态、字段、表单或资源路由。
- 可见文案出现 `Finance Center`、`Business Center`、`Data Center`、`Candao` 作为繁中默认品牌。
- 出现假 Logo、假客户、假认证、假接入状态、假 SLA 或未授权指标。
- 组件圆角、渐变、阴影和图标使页面落回通用 SaaS 模板。

## 推荐进入高保真顺序

1. 先用 T48 HTML 样例和本蓝图确认页面角色。
2. 确认后再进入 Stitch / Figma 单屏生成。
3. 首轮只生成页面母版，不强行塞满禁用词和逐条 QA。
4. 下载 HTML 和截图后再跑内容覆盖、domain-copy、静态风险和渲染 QA。

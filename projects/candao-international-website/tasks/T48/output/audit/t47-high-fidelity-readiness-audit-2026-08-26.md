## 为什么“内容覆盖 100%”仍然不够

高保真前置不是只检查文字是否出现。它必须回答：

- 这个页面在网站里的正式角色是什么；
- 首屏 5 秒内让访客理解什么；
- 每一屏由什么组件承载；
- 组件里的状态、字段、数据、异常和下一步是什么；
- 哪些内容默认可见，哪些内容通过 Tab、Accordion、详情卡或表单摘要承载；
- 哪些素材是真实 / 授权 / 示意，缺失时如何降级；
- 生成后如何判定“像首页风格”而不是“蓝色 SaaS 模板”。

T47 目前只完成第一层：内容没有丢。它没有完成第二层：内容被页面化、组件化、产品化。

## 高保真前置门槛

后续三合一页面必须同时满足以下门槛，才允许进入 Stitch / Figma / React 生产：

1. 页面角色明确  
   默认页面名改为 `接入評估中心 / Desktop 1440 / TC`，页面任务是帮助采购方、IT 和运营团队完成接入可行性、相似案例和资源下一步的评估。

2. 首屏有产品化判断界面  
   Hero 不能只放三张路径卡。首屏必须出现接入评估工作台：系统来源、接口对象、同步状态、异常回传、推荐演示模块。

3. 模块不再是内容清单  
   每个模块必须是页面组件：Hero product stage、System Fit Workbench、Case Proof Board、Resource Router、Decision Matrix、Demo Summary Form。

4. 内容覆盖变成模块覆盖  
   仍保持 100% 内容可追溯，但不强迫 224 个文本片段全部作为同级可见文本堆在页面里。每条内容必须映射到默认可见、交互展开、详情卡、表单摘要或后续页面入口。

5. 视觉风格按首页 DNA 执行  
   继承真实餐饮运营摄影、产品 UI 跨画布舞台、深色连接中枢、白底案例证明、深色数据带、白底 CTA，不只是借用颜色。

6. 事实边界清楚  
   可用：PPT 授权规模数据、实名案例、旧官网 / PPT 产品能力。  
   不可用：假客户 Logo、假认证、假 SLA、假接入状态、未确认合作伙伴承诺、`Finance Center` 可见英文。

7. 生成 prompt 分层  
   首轮 prompt 只描述页面目的、构图、关键模块和内容白名单；禁用词和逐条覆盖放到 QA 与 cleanup edit。

## T47 的处理结论

- T47 可以保留为“内容合并和覆盖率证据”。
- T47 不应作为高保真页面直接上传或直接生成。
- T47 的 Stitch prompt 不应继续原样使用。
- 下一步应使用 T48 页面蓝图和 T48 v3 prompt 作为新的高保真前置输入。

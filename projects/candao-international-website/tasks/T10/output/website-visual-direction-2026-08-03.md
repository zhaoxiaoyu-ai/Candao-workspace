## 2. Visual Concept

### 2.1 总视觉概念

```text
Operational Clarity for Global Restaurant SaaS
```

中文解释：

用真实餐饮营运场景建立行业可信感，用结构化 SaaS UI Motion 解释订单、门店、配送、数据和系统连接，让复杂餐饮运营变得清晰、可见、可管理。

### 2.2 核心视觉判断

Candao 国际官网不应被设计成泛科技官网，也不应被设计成产品截图说明书。

Real Restaurant Operations

Purposeful Product Motion

Global B2B Trust

## 3. Visual Direction

### 3.1 全站视觉原则

| 原则 | 执行方式 |
| --- | --- |
| 真实优先 | 首页和核心页面优先使用餐饮运营、门店协作、后厨出餐、配送协调等真实商业场景 |
| UI 解释产品 | 产品价值通过 `UI Overlay`、`Capability Map`、`Data Flow`、`Order Queue`、`Delivery Timeline` 表达 |
| 克制高级 | 使用国际 B2B SaaS 的清晰布局、节制色彩和稳定组件，不做强营销式视觉 |
| 信息清楚 | 页面视觉必须服务 5 秒理解、路径识别和 Demo 转化 |
| 动效有目的 | Motion 只用于解释流程、状态变化和系统连接，不做无意义视觉装饰 |

### 3.2 禁止方向

- 纯 3D 科技视觉；
- 抽象 AI 背景；
- 粒子、数据隧道、芯片、网络球体；
- 普通办公室、会议室、商务握手；
- 大量插画替代真实业务；
- 软件截图密集平铺；
- 未授权客户 Logo、门店照片、客户评价或具体数据；
- 所有页面同等高保真和同等 Motion 投入。

## 4. Typography

### 4.1 字体方向

| 用途 | 推荐方向 | 说明 |
| --- | --- | --- |
| English Headline | `Inter Tight` / `Neue Haas Grotesk` / `Söhne` 风格 | 几何、清晰、企业级 SaaS 感，不使用过度科技字体 |
| English Body | `Inter` / `Suisse Intl` 风格 | 可读性优先，适合长段 B2B 内容 |
| 繁体中文 | `Noto Sans TC` / `Source Han Sans TC` / `PingFang TC` | 香港及亚洲市场友好，字重完整 |
| UI Label | `Inter` / `Noto Sans TC` 混排 | 用于状态、标签、表单、数据摘要 |

### 4.2 字体层级

| 层级 | 用途 | 方向 |
| --- | --- | --- |
| Display | Home Hero、核心页面 Hero | 大号、稳重、行高紧凑但不压迫 |
| H1 / H2 | 页面标题、模块标题 | 清楚表达页面角色，不使用装饰性字体 |
| Body | 正文说明 | 中等字号、足够行高，支持中英文双语审阅 |
| Label | UI Demo、卡片标签、状态标签 | 小号但清晰，避免过度压缩 |

### 4.3 排版规则

- 不使用负字距。
- 不用视口宽度动态缩放字体。
- Hero 标题可以大，但产品面板、表单和卡片内标题必须收敛。
- 中英文混排时，英文关键词保留原文，但中文说明不应被英文术语淹没。

## 5. Color System

### 5.1 色彩方向

品牌主色需以 Candao 现有品牌资产为准。以下为 T10 视觉方向建议，不作为最终品牌色锁定。

推荐色彩逻辑：

```text
Warm Operational Neutral
+
Signal Green
+
Service Amber
+
SaaS Data Colors
```

### 5.2 Token 建议

| Token | 建议方向 | 用途 |
| --- | --- | --- |
| `Primary / Operational Green` | 深绿色或清晰绿色 | Primary CTA、关键连接状态、成功状态 |
| `Accent / Service Amber` | 温暖琥珀色 | 餐饮现场、人流、配送高峰、强调提示 |
| `Neutral / Ink` | 近黑灰绿或深墨色 | 文字、导航、页脚、深色 UI 面板 |
| `Neutral / Cloud` | 冷白或浅灰白 | 页面背景、卡片底色、留白区域 |
| `Line / Mist` | 中性浅灰 | 分割线、UI 边框、流程线 |
| `Status / Blue` | 清晰蓝 | 信息状态、系统连接、数据流 |
| `Status / Red` | 克制红 | 异常状态、配送风险、错误提示 |

### 5.3 色彩使用规则

- 全站不做单一绿色主题堆叠，应使用中性空间、绿色信号和琥珀场景光形成层次。
- `Primary CTA` 应始终清晰，不被 Hero 图片或 UI Overlay 淹没。
- UI Demo 中的状态色只服务理解：订单进入、处理中、配送中、异常、完成。
- 深色块可用于 Hero 或 Product UI Demo，但不应让全站变成深色科技界面。
- 色彩对比必须满足可读性，尤其是视频背景上的文字与按钮。

## 6. Photography & Media Direction

### 6.1 摄影风格

推荐风格：

```text
Large Editorial Restaurant Operations Photography
```

执行说明：

- 真实商业餐饮环境；
- 不过度摆拍；
- 有人、有动作、有运营信息；
- 能看见前台、后厨、出餐、接单、配送、门店协作；
- 画面干净，适合叠加 SaaS UI Overlay；
- 人物不需要直视镜头，更适合表现工作流。

### 6.2 页面素材方向

| 页面 / 模块 | 推荐摄影或媒体 | 目的 |
| --- | --- | --- |
| Home Hero | 餐厅高峰营运、前台接单、厨房出餐、门店协作视频或大图 | 5 秒内建立餐饮运营真实感 |
| Home Trust / Data Proof | 抽象化能力信任层、系统连接图、服务支持图标 | 在无客户授权素材时建立可信基础 |
| Product Showcase | 场景图 + 半真实 SaaS UI Overlay | 解释 Candao 连接订单、菜单、配送和数据 |
| Products / Platform | Capability Map、系统连接、订单流、数据回流 | 表达统一平台，不做产品目录 |
| Order Management | 门店接单场景、订单队列 UI、状态变化 | 展示多渠道订单集中处理 |
| Delivery Management | 出餐、取餐、配送状态、地图和队列 | 展示高峰配送协调 |
| Integrations Overview | 系统类别、连接线、数据流、Request Integration 入口 | 建立技术可信和合作入口 |
| Cases / Customers | Case Template、场景标签、授权状态 | 等待授权素材时保留证明结构 |
| Company / About | 团队协作、实施支持、餐饮运营支持场景 | 务实可信，不做过度品牌大片 |

### 6.3 素材来源优先级

1. 企业真实素材：门店、运营、实施、服务支持。
2. 产品录屏或真实产品截图：必须脱敏，不使用客户真实数据。
3. UI 重构动画：用于 Home、Platform、Order、Delivery 的演示。
4. 高质量商业摄影：仅选择符合餐饮运营场景的素材。
5. AI 辅助视觉探索：只用于 Moodboard 或方向探索，不直接替代真实业务素材。

### 6.4 禁用素材

- 普通办公室会议；
- 商务握手；
- 过度微笑客服；
- 与餐饮运营无关的城市夜景；
- 食物特写但没有运营信息的库存图；
- 泛科技芯片、3D 球体、AI 光效、粒子背景；
- 未授权客户门店、Logo、员工肖像和评价。

## 7. Video Usage

### 7.1 Home Hero Video

推荐：

- 8 到 12 秒静音循环；
- 场景包含前台接单、后厨出餐、门店协作、配送交接；
- 镜头节奏稳定，不做广告片式快切；
- 画面预留左侧或中部文字空间；
- 叠加轻量 `SaaS UI Overlay`，展示订单流、门店状态、配送状态和数据回流。

不推荐：

- 只有食物或餐厅氛围，没有运营动作；
- 过度戏剧化餐饮广告风格；
- UI 层过重导致看不见真实场景；
- 视频亮度过高或过暗，影响标题可读。

### 7.2 Product Motion Video

适用：

- Products / Platform Capability Map；
- Order Management 4-step UI Demo；
- Delivery Management 4-step UI Demo。

形式：

```text
Scene
→ Action
→ UI State
→ Business Result
```

要求：

- 每段 Motion 必须有静态截图等价状态；
- 移动端降级为步骤卡或滑动卡；
- 不使用真实客户数据；
- 不进入 L4 Product Simulation，除非 T11/T13 明确追加。

## 8. Page Layout Direction

### 8.1 全站布局

推荐方向：

```text
Editorial SaaS Layout
+
Structured Product Sections
+
Clear Conversion Path
```

布局规则：

- 页面 Section 使用全宽带状结构或无框布局，避免卡片套卡片。
- 内容宽度建议控制在清晰可读范围，桌面以 12-column grid 为基础。
- Hero 不放入卡片容器，保留开放视觉空间。
- 核心产品区使用横向流程、能力地图和 UI Demo 组合。
- 模板页复用组件，减少独立视觉探索。

### 8.2 页面节奏

| 页面 | 布局节奏 |
| --- | --- |
| Home | 大 Hero → 信任层 → 问题切换 → 产品展示 → 解决方案 → 集成 → 案例模板 → CTA |
| Products / Platform | Hero → Capability Map → Platform UI Demo → Business Outcome → Product Entry → CTA |
| Order Management | 场景问题 → 订单流程 → UI Demo → 状态和总部视图 → CTA |
| Delivery Management | 高峰问题 → 调度流程 → 地图 / 队列 UI Demo → 异常回流 → CTA |
| Integrations Overview | Hero → Category Map → Connection Flow → Request Integration → CTA |
| Contact / Book a Demo | Intent Selection → Progressive Form → Trust Note → Submit Feedback |

### 8.3 Responsive Layout

| 断点 | 规则 |
| --- | --- |
| Desktop 1440 | 横向流程、能力地图、双栏 Hero、完整 UI Demo |
| Tablet 768 | 保留主要分栏，UI Demo 降低同时显示的信息量 |
| Mobile 390 | 单列内容流，Capability Map 改为步骤卡，UI Demo 改为 Swipe / Stepper |

## 9. UI Style

### 9.1 UI 总方向

```text
Semi-real SaaS UI
```

说明：

UI 不应是完全真实后台截图堆叠，也不应是过度抽象的线框。T10 推荐使用半真实产品 UI：保留订单、状态、门店、配送、数据等真实业务结构，但使用脱敏数据和统一视觉系统重构界面。

### 9.2 UI 组件方向

| 组件 | 视觉规则 |
| --- | --- |
| Dashboard | 清晰层级、少量关键指标、状态摘要，不做密集报表 |
| Cards | 圆角 8px 或更小，信息点单一，Hover 不改变尺寸 |
| Data Flow | 使用细线、节点、状态变化表达连接，不做复杂粒子线网 |
| Capability Map | 表达 Order、Menu、Delivery、Data、Integrations 的关系 |
| Order Queue | 左侧渠道来源，中央统一队列，右侧状态 / 门店 / 总部视图 |
| Delivery View | 地图、骑手状态、配送队列、异常提示形成清晰关系 |
| Form | 意图选择优先，字段分组清晰，错误和成功状态明确 |

### 9.3 UI 状态

必须定义：

- Default；
- Hover；
- Focus；
- Active；
- Selected；
- Loading；
- Success；
- Warning；
- Error；
- Disabled。

## 10. Product Showcase Direction

### 10.1 Home Product Showcase

目标：

让用户理解 Candao 是一个连接餐饮运营关键环节的平台，而不是功能列表。

推荐视觉：

```text
Order enters
→ Menu / Store status sync
→ Delivery status update
→ Data returns to dashboard
```

展示方式：

- 中央使用 `Capability Flow`；
- 五类能力入口：Order、Menu、Delivery、Data、Integrations；
- 每个能力只显示一句价值摘要和一个后续入口；
- 动效使用 L2-L3，不做完整产品模拟。

### 10.2 Products / Platform Capability Map

目标：

表达 Candao 如何连接系统、流程和运营数据。

推荐结构：

```text
Ordering Channels
→ Candao Platform
→ Stores / Delivery / Data
→ Headquarters Visibility
```

视觉方式：

- 中央平台节点；
- 周围连接订单渠道、POS、Delivery、Payment、Loyalty、Data；
- 使用温和流动线表达连接；
- 点击或滚动切换 Order、Menu、Delivery、Data、Integrations 五个能力视图。

### 10.3 Order Management UI Demo

4-step storyboard：

| Step | 视觉状态 | 业务表达 |
| --- | --- | --- |

| 3 | 门店处理订单状态 | 前线执行清晰 |

### 10.4 Delivery Management UI Demo

4-step storyboard：

| Step | 视觉状态 | 业务表达 |

## 11. Motion Style

### 11.1 动效总原则

```text
Purposeful Motion for Operational Understanding
```

动效只做三件事：

1. 解释流程；
2. 显示状态变化；
3. 引导下一步行动。

### 11.2 动效等级

| Level | 用途 | T10 执行 |
| --- | --- | --- |
| L1 Hover / Reveal | 卡片、导航、轻量内容页 | 默认使用 |
| L2 Scroll Animation | Home、Solutions、Integrations | 用于节奏和流程呈现 |
| L3 Guided Interactive Demo | Platform、Order、Delivery、Contact | 核心产品页重点使用 |
| L4 Product Simulation | 后续销售 Demo 或产品演示 | T10 不默认进入 |

### 11.3 Motion 参数方向

| 类型 | 方向 |
| --- | --- |
| Scroll reveal | 慢、稳定，避免跳动 |
| Stepper transition | 300ms 到 500ms，状态切换清晰 |
| UI status update | 使用轻量高亮、线条流动、状态 chip 切换 |
| CTA hover | 轻微颜色或阴影变化，不改变按钮尺寸 |
| Map / Delivery motion | 只显示必要状态，不做复杂地图模拟 |

### 11.4 Mobile Downgrade

- Hero 视频降级为静态封面 + 轻量 UI 状态；
- Capability Map 降级为步骤卡；
- Order / Delivery UI Demo 降级为 Swipeable 4-step cards；
- Contact 表单保持单列，Intent Selection 放在首屏附近；
- `prefers-reduced-motion` 使用静态状态或简单 Fade。

## 20. Hero Composition Rule

### 20.1 Desktop 1440 构图建议

```text

```

| 层级 | 构图规则 |

## 21. Brand Color Adaptation Process

T10 的 Color System 只是方向，不代表最终品牌色。T11 必须基于 Candao 现有品牌资产做品牌色适配。

### 21.1 色彩落地流程

```text
Existing Brand Asset
→ Color Extraction
→ Digital Adaptation
→ Accessibility Check
→ Token Definition
→ Component Application
→ Visual Review
```

| 步骤 | 执行说明 | 输出 |
| --- | --- | --- |
| Existing Brand Asset | 收集 Logo、品牌手册、现有官网、销售材料中的品牌色 | Brand color source |

| Component Application | 应用到 CTA、Header、Cards、UI Demo、Forms | Component preview |
| Visual Review | 检查是否符合 `Operational Clarity for Global Restaurant SaaS` | Approval note |

### 21.2 色彩边界

- 不应由 T11 重新发明一套与 Candao 品牌无关的绿色体系。
- 如果 Candao 现有主色不适合大面积 Web 使用，应保留品牌识别，并将其转化为 CTA、状态、重点信息或 Accent。
- UI Demo 的数据色必须服务业务理解，不做彩虹式 Dashboard。
- 色彩必须同时验证浅色背景、深色 Hero、表单状态和移动端可读性。

## 23. Visual Review Checklist

T11 完成后必须按以下清单审核。

### 23.1 品牌检查

- 是否能在 5 秒内建立 Candao 是国际餐饮运营 SaaS 平台？
- 是否延续 `Operational Clarity for Global Restaurant SaaS`？
- 是否专业、务实、可信、国际化？
- 是否避免“行业领先”“一站式赋能”等国内软件官网感？

### 23.2 视觉检查

- 是否优先使用真实餐饮运营场景？
- 摄影 / 视频是否包含运营动作，而不是普通餐饮氛围？
- 是否避免普通办公室、商务握手、泛科技、抽象 AI、粒子和 3D 球体？
- Hero 是否有足够负空间支持标题和 CTA 可读？

### 23.3 产品检查

- UI 是否解释订单、门店、配送、数据和系统连接？
- Product Showcase 是否是能力流，而不是功能列表？
- Order / Delivery UI Demo 是否有清晰 4-step storyboard？
- UI 数据是否脱敏和抽象化？

### 23.4 动效检查

- Motion 是否服务理解，而不是装饰？
- Home 和 Platform 是否控制在 L2-L3？
- Order / Delivery 是否使用 Guided Demo，而不是完整产品模拟？
- Mobile 和 `prefers-reduced-motion` 是否有降级方案？

### 23.5 转化检查

- `Book a Demo` 是否在关键路径可见？
- Contact 表单是否先分流意图，再收集 Lead Qualification？
- CTA 是否被背景视频、UI Overlay 或其他视觉元素削弱？
- Trust fallback 是否在无客户授权素材时仍成立？

### 23.6 交付检查

- 是否包含 Desktop 1440 和 Mobile 390 的核心 Frame？
- 是否包含 Design Tokens、Components 和 Motion Storyboards？
- 是否标注每个页面的 Visual Priority、Fidelity Level、Interaction Level、Asset Requirement、Copy Status 和 Open Questions？
- 是否能进入 T12 审核和 T13 最终整合？

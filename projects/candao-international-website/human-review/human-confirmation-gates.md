# 餐道国际官网人工确认关卡

版本：v1.0  
日期：2026-08-15  
适用范围：餐道国际官网策略、内容、原型、Figma / Stitch、前端原型、行业文案规则和项目知识库更新。

## 0. 原则

人工不需要参与每一个执行步骤。Agent 可以自动完成资料整理、需求拆解、页面结构、文案初稿、低保真原型、自动 QA 和一般性修正。

人工必须参与的是 AI 不能自行判定真伪、优先级、范围和规则适用层级的决策节点。

本项目采用：

```text
3 个项目强制人工确认点
+ 1 个永久规则更新审核点
```

Agent 可以提出建议、证据和风险，但不得自行把以下状态标记为 approved。

## 1. 关卡一：原始业务事实确认

发生时机：Agent 完成资料整理、证据清单、业务上下文、术语表、指标表和状态表之后。

确认状态：

```yaml
business_facts: approved
```

人工需要确认：

- 当前有效资料版本和权威顺序。
- 核心业务目标。
- 目标用户和角色。
- 核心业务流程。
- 标准术语。
- 业务状态和异常状态。
- 指标定义、数据口径和来源。
- 当前项目明确不做的内容。
- 哪些内容已经确认。
- 哪些内容仍然是假设。

Agent 可以做：

- 提取事实、术语、指标、状态和冲突。
- 标注来源、缺口和合理假设。
- 输出决策摘要。

Agent 不得做：

- 自行选择冲突资料中的最终版本。
- 自行定义指标口径。
- 自行确认状态、客户、Logo、认证、SLA 或公开数字。

## 2. 关卡二：需求基线和范围确认

发生时机：Agent 完成需求理解、隐性需求识别、页面角色、用户路径、范围拆分和冲突判断之后；进入完整页面内容、原型、Figma / Stitch 或前端实现之前。

确认状态：

```yaml
requirement_baseline: approved
```

人工需要确认：

- 项目目标。
- 核心用户。
- 核心任务。
- 本期必须包含。
- 建议包含。
- 本期不包含。
- 核心页面范围。
- 核心流程。
- 主要业务规则。
- 已采用的合理假设。
- 仍待确认的问题。

Agent 可以做：

- 推演页面结构、用户路径、核心流程和候选范围。
- 标记需求冲突、缺失状态、过大范围和泛化风险。

Agent 不得做：

- 自行决定哪个隐性需求本期必须做。
- 自行扩大页面范围。
- 自行改变核心流程或优先角色。
- 在未确认范围上继续生成高保真或生产前端。

## 3. 关卡三：最终业务验收

发生时机：Agent 完成原型、内容、自动 QA、一轮修正和需求回溯之后。

确认状态：

```yaml
final_business_acceptance: approved
```

人工需要采用任务驱动方式验收，而不是只浏览页面。

建议验收任务：

- 决策者能否在 5 秒内理解餐道不是泛 SaaS，而是餐饮与零售 O2O 营运中枢。
- 总部运营能否找到多平台订单、门店、餐单、异常和报表的关系。
- IT 能否理解 AMS / Connector 连接哪些系统类型和数据流。
- 配送主管能否理解 DMS / iDMS 的派单、骑手、第三方溢出和异常处理。
- 财务或管理层能否理解 CDBI / Finance Center 的数据来源、对账对象和异常口径。
- 采购方能否从 Customers / About / Demo 判断可信度和下一步联系路径。

Agent 可以做：

- 自动检查需求覆盖、页面死路、术语一致、内容完整、文案长度、禁止词、空状态、异常状态和锁定文案。
- 输出验收任务清单和未通过项。

Agent 不得做：

- 自行判断业务人员是否认可工作节奏。
- 自行认定页面足以支持真实业务决策。
- 自行把原型标记为业务验收通过。

## 4. 管理关卡：永久规则和知识库更新审核

发生时机：准备把一次人工修改、项目经验或术语调整写入 `domain-copy/`、Skill、企业词典、行业规则或全局 `AGENTS.md` 之前。

确认状态：

```yaml
permanent_rule_update: approved
```

人工需要确认：

- 这次修改是单页特殊要求、项目规则、企业术语、行业规则，还是全局规则。
- 是否会污染其他页面、其他项目或其他行业。
- 是否需要新增回归案例。
- 是否需要更新术语表、文案规则、QA 脚本或 Skill。

写入层级：

| 修改类型 | 存放位置 |
| --- | --- |
| 单个页面特殊修改 | 当前页面内容或任务输出 |
| 当前项目统一规则 | 项目 `human-review/`、`domain-copy/` 或 `RULES.md` |
| 当前企业统一术语 | 企业业务词典或项目术语表 |
| 行业通用规则 | 对应行业 Skill |
| 所有项目都适用的表达规则 | 全局规则 |

Agent 可以做：

- 提出更新建议。
- 标注适用范围和风险。
- 写入候选队列。

Agent 不得做：

- 因用户改了一次就自动写入永久规则。
- 把个人偏好当作行业标准。
- 把当前项目术语污染到其他项目。

## 5. 额外触发人工确认的情况

即使已经通过需求基线，遇到以下情况也必须进入决策队列：

1. 两份权威资料互相矛盾。
2. 需要创造新的业务规则。
3. 缺少关键指标口径。
4. 需要改变核心流程。
5. 新增页面会明显扩大项目范围。
6. 涉及角色权限或数据可见范围。
7. 涉及法律、监管、安全或隐私要求。
8. 需要用虚构数据模拟真实经营结论。
9. 需要删除已经确认的功能或内容。
10. 需要将项目经验升级为永久规则。

原则：进入决策队列不代表所有工作都停止。Agent 可以继续完成不受影响的部分。

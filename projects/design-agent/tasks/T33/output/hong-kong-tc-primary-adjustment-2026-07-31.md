# T33：香港繁中优先修订说明

## 1. 修订结论

T32 原结论默认偏“国际英文通用 + 香港案例支撑”。根据用户最新要求，后续官网需求应调整为：

> CanDao 官网新版第一阶段以香港地区为主要服务市场，网页默认使用繁体中文，英文作为兼容语言、技术术语和国际合作辅助入口。

因此，后续设计和研发不应把英文站作为默认主站，也不应把多国家落地页作为 MVP 主线。MVP 应先把香港市场讲清楚：香港客户、香港外卖 / 配送 / POS / 支付生态、香港联系方式、香港服务能力、香港合规与签约主体。

## 2. 对 T32 的关键替换

| T32 原假设 | T33 调整后 |
| --- | --- |
| 第一阶段以香港 + 国际英文通用市场为主 | 第一阶段以香港地区为主，繁体中文为默认语言 |
| 支持英文 / 繁中内容结构 | 繁体中文主站完整可用，英文作为兼容语言和辅助路径 |
| 国际客户理解效率 | 香港餐饮客户、香港餐饮集团、中国品牌入港团队、香港本地技术伙伴的理解效率 |
| 国际 SEO | 香港繁中 SEO 优先，英文 SEO 辅助 |
| 国家落地页 P1 | 国家落地页降级，香港本地页面与英文兼容页优先 |
| GDPR 作为国际站合规重点之一 | 香港私隐、Cookie、Privacy、Terms、DPA、数据存放优先；GDPR 在重新面向英国 / 欧盟市场时再升为 P0 |
| Contact Sales / Book a Demo 英文 CTA | 中文主标签 + 英文辅助，例如 `預約示範 Book a Demo`、`聯絡銷售 Contact Sales` |
| 多市场服务能力 | 香港服务能力优先，其他地区只保留“可咨询 / 需确认” |

## 3. 语言策略

| 项目 | 要求 |
| --- | --- |
| 默认语言 | 繁体中文，建议使用香港用语和香港业务语境 |
| 英文角色 | 兼容语言、技术术语、国际伙伴和英文用户辅助入口 |
| 页面 URL | 建议根路径或 `/zh-hk/` 承载繁中主站；英文使用 `/en/` 或 `/en-hk/`，具体取决于域名和旧 URL 策略 |
| 语言切换 | 顶部导航提供 `繁中 / EN`，但默认进入繁中 |
| CTA 文案 | 繁中主文案 + 英文辅助，避免只有英文按钮 |
| 产品名 | 中文解释 + 英文产品 / 能力名并存，例如 `多渠道訂單管理 Multi-channel Order Management` |
| 表单 | 字段默认繁中；公司名、邮箱、系统名称、平台名称等允许英文输入 |
| SEO | `zh-HK` 为主；英文页面使用 `en-HK` 或 `en`，并配置 `hreflang` |

## 4. 香港地区 MVP 重点

| 模块 | 调整后重点 |
| --- | --- |
| 首页 | 用繁中说明 CanDao 如何帮助香港餐饮品牌统一外卖订单、门店菜单、配送和数据 |
| Solutions | 以香港餐饮场景组织：连锁餐饮、多门店营运、外卖营运、自家渠道点餐、配送管理 |
| Products | 产品页标题优先繁中，英文作为副标题或括号补充 |
| Integrations | 优先展示香港相关外卖、POS、配送、支付、CRM / 会员系统；每项必须标注已上线 / 可定制 / 需查询 |
| Customers | 优先展示香港案例：Pizza-Box、JIA Group、Paisanos、Jardine 等，前提是授权明确 |
| Contact | 优先展示香港销售、WhatsApp、邮箱、办公室、营业时间和响应承诺 |
| About / Trust | 解释 CanDao 与 51WM Company Ltd、香港服务团队、签约主体和可公开公司资料 |
| Security / Legal | 香港私隐、Cookie、Privacy、Terms、DPA、数据存放和安全认证优先 |
| SEO / Content | 香港繁中关键词、香港餐饮科技场景、FAQ、案例和本地内容运营 |

## 5. 需要从 MVP 降级的内容

| 内容 | 调整 |
| --- | --- |
| 多国家落地页 | 降为 P2，除非明确要做新加坡 / 英国 / 澳洲等市场 |
| 英文完整资源中心 | 可 P1；MVP 英文仅需覆盖核心销售链路 |
| 国际通用 Pricing | 暂不建议公开价格；香港也建议先用 `聯絡銷售 Contact Sales` |
| Start Free | 继续不建议作为 MVP 主 CTA |
| GDPR 深度说明 | 降为 P1 / P2；若收集欧盟用户或面向欧盟营销，再升为 P0 |
| AI IM / MCP / WorkBuddy | 仍不建议进入 MVP 主导航，除非有香港市场明确价值和交付资料 |

## 6. 新的首屏判断

首页首屏不应再以英文 SaaS 口吻开场，而应让香港用户一眼看懂：

- 这是服务香港餐饮营运的系统。
- 能统一 Foodpanda、Deliveroo 等外卖订单和门店资料。
- 能减少漏单、错单、菜单重复维护和配送异常。
- 有香港客户和本地服务经验。
- 可以用繁中沟通，并保留英文咨询能力。

示例方向：

| 层级 | 示例 |
| --- | --- |
| 主标题方向 | `為香港餐飲品牌統一訂單、餐單、配送與營運數據` |
| 支持文案方向 | `連接外賣平台、POS、配送與自家點餐渠道，幫助多門店團隊減少重複操作、漏單和高峰期履約壓力。` |
| 主 CTA | `預約示範 Book a Demo` |
| 次 CTA | `查看方案 Explore Solutions` |

以上只是方向示例，最终文案仍需内容阶段打磨。

## 7. 待确认问题更新

| 问题 | 为什么重要 | 阻塞级别 |
| --- | --- | --- |
| 香港站是否以根路径直接展示繁中，还是使用 `/zh-hk/`？ | 影响 SEO、旧 URL、语言切换和开发路由 | 高 |
| 英文兼容是完整英文站，还是只覆盖首页、产品、集成、联系等核心链路？ | 影响内容工作量和 MVP 排期 | 高 |
| 香港可公开客户和案例有哪些？ | 决定信任模块强度 | 高 |
| 香港已正式支持的平台、POS、配送、支付、CRM / 会员系统清单是什么？ | 决定 Integrations 页真实性 | 高 |
| 香港销售电话、WhatsApp、邮箱、办公室地址、营业时间和响应时间是什么？ | 决定 Contact 页能否上线 | 高 |
| 香港数据存放、私隐政策、Cookie、Terms、DPA 是否齐备？ | 决定合规上线风险 | 高 |

# 餐道官网极简但全面的交互呈现方案

## 1. 结论

可以做到，而且这是当前最合适的方向。

关键不是减少官网要表达的内容，而是减少用户“默认看到的内容”。当前截图中的内容基本完整，但静态页面一次性展开了太多层级。建议改为：

> 首页默认极简，完整内容通过交互逐层出现。

## 2. 当前截图判断

当前截图已经覆盖了官网应表达的主要内容：

- 首屏定位和 CTA。
- 品牌 / 门店 / 订单 / 可用性等信任指标。
- 行业挑战。
- 产品矩阵。
- 集成与合作伙伴。
- 客户案例。
- 多意图转化入口。

问题不在内容选择，而在信息呈现方式：

- 首页纵向长度过长。
- 多个模块都采用并列展示，视觉节奏相似。
- 用户还没表达兴趣，就已经看到大量产品、集成、案例和指标。
- 案例、产品、集成这些“验证型内容”应在用户点击后展开，而不是默认铺满。

## 3. 设计原则

| 原则 | 说明 |
| --- | --- |
| 默认只展示结论 | 每个模块默认只露出一句话价值和一个动作 |
| 点击后展示证据 | 功能、案例、集成、指标等内容按需展开 |
| 首页负责分流 | 首页不承担完整说明书角色 |
| 二级页面负责深度 | 产品详情、集成目录、案例详情承接完整信息 |
| 用户一次只做一个判断 | 每一屏只回答一个问题 |

## 4. 推荐首页结构

### 4.1 默认态

首页默认只保留 5 个模块：

1. 首屏定位：餐道是什么，主 CTA 是什么。
2. 信任摘要：3 到 4 个关键证明，不展示完整 Logo 墙。
3. 需求选择器：用户选择自己关心的问题。
4. 动态能力区：根据选择展示对应产品 / 集成 / 案例摘要。
5. 下一步分流：预约示范、联系销售、合作伙伴、客户支持。

### 4.2 展开态

完整内容通过以下方式出现：

| 内容 | 默认态 | 交互后 |
| --- | --- | --- |
| 行业挑战 | 只显示 3 个问题标签 | 点击后展开对应痛点、解决方式和产品入口 |
| 产品矩阵 | 只显示 3 个能力组 | Tab 切换后显示对应产品摘要和详情入口 |
| 集成与合作伙伴 | 只显示 5 类集成分类 | 点击分类后进入筛选列表或打开轻量抽屉 |
| 客户案例 | 只显示 1 个主案例摘要 | 切换案例后展示指标、使用产品和详情入口 |
| 联系转化 | 只显示主 CTA | 点击后按意图选择表单路径 |

## 5. 建议交互模型

### 模型 A：需求选择器

位置：首页首屏下方。

默认展示：

- 想统一多平台订单。
- 想减少菜单重复维护。
- 想提升配送效率。
- 想打通系统和数据。

点击后展示：

- 对应问题说明。
- 对应产品组合。
- 对应集成或案例。
- 下一步 CTA。

价值：让用户先选择问题，再展示内容，避免首页同时铺开所有模块。

### 模型 B：产品能力 Tab

位置：产品矩阵区域。

默认只显示三个能力组：

- 订单与菜单。
- 点餐与配送。
- 数据与集成。

Tab 展开后再显示具体产品：

- 订单管理。
- 菜单与门店管理。
- 自有点餐。
- 配送编排。
- 数据与对账。

价值：保留产品完整性，但默认视觉只显示高层分组。

### 模型 C：集成分类抽屉

位置：集成与合作伙伴区域。

默认只显示分类：

- 外卖平台。
- POS。
- 支付。
- 配送。
- CRM / 会员。

点击分类后打开右侧抽屉或跳转 `Integrations` 页面：

- 集成状态。
- 支持方式。
- 请求新集成。
- 合作伙伴申请。

价值：集成能力很重要，但它应该成为可探索的目录，而不是首页的方块列表。

### 模型 D：案例轮播 / 对比卡

位置：客户案例区域。

默认只显示一个主案例：

- 客户类型。
- 使用产品。
- 1 到 2 个结果指标。
- 查看案例。

切换后展示其他案例。

价值：案例是信任证明，不必一次展示三行以上；用户有兴趣再看更多。

### 模型 E：多意图联系向导

位置：底部转化区或固定 CTA。

默认显示一个按钮：

- 选择适合您的下一步。

点击后出现四个入口：

- 预约示范。
- 联系销售。
- 合作伙伴。
- 客户支持。

价值：保留完整转化路径，但默认界面更轻。

## 7. 与竞品结论的对应关系

| 竞品共性 | 交互化处理 |
| --- | --- |
| Deliverect 的信息架构 | 用清晰导航和集成目录承接，不把目录铺满首页 |
| TabSquare 的场景叙事 | 首屏和问题选择器强调餐饮经营场景 |
| Aigens 的产品深度 | 通过产品详情页、展开面板和 FAQ 承接 |
| 集成生态是核心 | 首页只预览，点击后进入可搜索集成页 |
| 联系分流重要 | 用底部向导或联系页分流，而不是堆多个按钮 |

## 8. 下一步建议

下一轮建议只出一张“交互版低保真推荐稿”，重点展示：

- 默认态：首页看起来有多轻。
- 点击行业挑战后的展开态。
- 切换产品能力 Tab 后的状态。
- 打开集成分类抽屉后的状态。
- 底部联系向导展开后的状态。

这样能同时证明两件事：

- 默认页面足够极简。
- 官网内容依然完整，只是被交互组织起来。

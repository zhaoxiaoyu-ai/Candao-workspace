# 餐道官网多页面低保真交互原型 v2

## 1. 产物

| 文件 | 说明 |
| --- | --- |
| `multipage-interactive-wireframe-v2.html` | 单文件可打开的多页面低保真交互原型 v2 |
| `t44-home.png` | 首页桌面截图 |
| `t44-products.png` | 产品总览页桌面截图 |
| `t44-mobile-home-menu.png` | 移动端首页菜单截图 |

## 2. 为什么做 v2

T43 虽然修正了导航不应是首页锚点的问题，但首页被做成了“页面入口目录”，更像说明书或路由演示，不像真正的餐饮科技 SaaS 官网。

v2 的目标是保留 T43 正确的多页面结构，同时重建首页的宣传作用和第一感官说服力。

## 3. 本轮修正重点

- 首页不再只放入口卡片，而是改为连续叙事：
  首屏品牌定位与经营结果 -> 信任判断 -> 经营问题切换 -> 平台能力切换 -> 产品矩阵预览 -> 集成可信 -> 客户证明 -> 为什么选择餐道 -> 转化分流
- 首页新增三组关键交互：
  - 首屏焦点切换
  - 经营问题切换
  - 平台能力切换
- 其他页面继续保留 T43 已完成的结构与交互：
  - 解决方案总览
  - 产品总览
  - 5 个产品详情
  - 集成目录
  - 客户案例
  - 资源 / FAQ
  - 关于 / 信任
  - 联系我们

## 4. 首页策略变化

### T43 首页

- 偏入口目录
- 强调“从首页去别的页面”
- 宣传力不足
- 更像站点地图

### T44 首页

- 偏品牌与业务结果
- 先让用户理解价值和适配度
- 用交互切换承接问题与能力
- 再把用户导向产品、集成、案例和联系页

## 5. 可体验交互

- 首屏焦点区支持自动轮播和点击切换
- 经营问题区点击后切换右侧产品承接方式
- 平台能力区点击后切换当前能力模块和链路说明
- 顶部导航继续使用独立页面路由，不回退到首页锚点
- 产品矩阵卡片仍可进入产品详情页
- 移动端菜单可展开

## 6. 验证结果

- JS 语法检查通过
- Playwright + 本机 Chrome 验证通过
- 已验证：
  - 首页首屏渲染正常
  - 首屏焦点切换正常
  - 经营问题切换正常
  - 平台能力切换正常
  - 跳转到产品总览正常
  - 移动端菜单展开正常

## 7. 后续建议

下一步如果继续深化，建议顺序如下：

1. 将单文件原型拆成真实多 HTML 或前端路由结构。
2. 为产品详情页补充更完整的痛点、收益、功能、FAQ 和案例承接。
3. 为集成目录增加详情抽屉或详情页。
4. 为客户案例增加详情页模板。
5. 将 T44 作为 Figma 高保真或网页生成 Agent 的首页策略基线。

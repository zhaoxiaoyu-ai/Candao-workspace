# T42 导航与页面路由修正说明

## 结论

当前 T42 首页交互原型中，顶部导航点击后滚动到首页对应模块。这种处理只适用于单文件低保真交互演示，不应作为正式官网的信息架构。

用户指出的问题成立：按竞品和 T34 PRD，首页内容与产品、解决方案、集成、案例、关于、联系等功能目录下的内容应相互独立。顶部导航应优先跳转到独立页面或页面族，而不是全部滚动到首页某个区域。

## 当时采用锚点滚动的考虑

T42 的目标是把 T41 的完整首页低保真稿做成可交互 HTML，并且保持单文件、低保真、不展开二级页面。因此当时用锚点 / 滚动模拟：

- 用户点击导航后能看到对应首页模块。
- 在一个 HTML 文件里验证首页叙事顺序和轻交互。
- 暂时不创建真实路由、产品详情页、集成目录页和联系页。

这属于原型效率处理，不是最终设计意图。

## 正式官网应如何处理

正式官网应采用多页面导航：

- `首页` 跳转 `/`。
- `解决方案` 跳转 `/solutions`，并可展开场景型下拉菜单。
- `产品` 跳转 `/products`，产品功能目录进入独立产品详情页。
- `集成与合作伙伴` 跳转 `/integrations` 或 `/partners`。
- `客户案例` 跳转 `/customers`。
- `资源` 跳转 `/resources` 或 `/support`。
- `关于我们` 跳转 `/about`。
- `联系我们` 跳转 `/contact`。

首页可以保留产品矩阵、集成预览和案例预览，但这些模块只是摘要和入口，不替代独立页面。

## 锚点允许出现的位置

锚点仍可用于：

- 产品详情页内部的小目录，例如“痛点 / 功能 / 工作流 / 集成 / FAQ”。
- 集成页内部的分类快速定位。
- Contact 页内部的表单区域跳转。
- 首页内部辅助浏览，但不能替代顶部一级导航。

## 后续修正要求

如果继续生成正式网页或高保真原型，需要把 T42 的顶部导航滚动逻辑改为真实页面路由，并补齐产品详情页、集成目录页、关于页和联系页的独立内容。

# 餐道官网官网式轻交互低保真修订

## 1. 修订结论

T39 的问题是把“交互”理解成了完整信息展开，因此页面仍然偏说明文档和后台展示。

本次修订改为常见官网的交互方式：

- 默认态只展示关键定位、主 CTA、少量证明和强视觉。
- 细节通过 hover、自动轮播、鼠标经过提示和局部高亮出现。
- 同一时间只展示一个交互状态，不把所有产品、集成、案例和联系路径同时摊开。

| 页面 2 | `wireframe-web-interaction-02-hover-carousel-state.png` | hover / 轮播状态：用户悬停到一个问题后，出现少量细节和同步视觉高亮 |

## 3. 页面 1：默认吸引态

默认态要像真实官网首页，而不是产品说明页。

保留：

- 一句话定位。
- 两个 CTA。
- 大面积产品 / 餐饮营运连接视觉。
- 3 个以内价值标签。
- 3 个以内信任证明。
- 3 到 4 个经营问题入口。
- 自动轮播进度点或进度线。

避免：

- 完整产品矩阵。
- 完整集成目录。
- 多行客户案例。
- 多个联系入口同时展开。
- 大段解释性文字。

## 4. 页面 2：hover / 轮播状态

交互态只表达“某一刻正在发生的变化”。

本页示例：

- 鼠标 hover 到“配送协同低效”。
- 对应卡片轻微高亮。
- 旁边出现一个小浮层，展示 2 到 3 条细节。
- hero 视觉同步切换到“配送协同”。
- 轮播进度切换到对应状态。
- 下方只露出“配送方案”的轻量 teaser，不展开完整详情。

## 5. 后续高保真规则

- 首页默认信息必须少，吸引力来自视觉、节奏和互动反馈。
- 每次 hover 只露出一小段信息，不能变成说明书。
- 自动轮播可在订单、菜单、配送、数据之间切换，但每一帧只讲一个重点。
- 产品详情、集成目录、案例详情和联系分流应由二级页面承接。
- 首页可用交互暗示“内容很完整”，但不需要把完整内容全部展示出来。

## 6. 推荐方向

后续如果进入 Figma 或高保真，建议以页面 1 为首页默认结构，以页面 2 为交互说明状态。

这两张不是两套方案，而是同一个官网首页的两个状态。

# 竞品共性结合与餐道官网方案补充

## 1. 读取结论

本次复读的两份文件分别承担不同作用：

- `generator_brief_expanded.json`：把 Aigens、Deliverect、TabSquare 的共性整理成网页生成约束。
- `generator-brief-expanded-usage-guide-2026-08-01.md`：说明该 brief 应与餐道 PRD 合并使用，不能直接替代 PRD。

核心判断：竞品分析不是要求首页展示更多内容，而是要求官网形成完整页面网络。首页应保持低密度，二级页面负责承接深内容。

## 2. 竞品共性

| 共性 | 对餐道官网的意义 | 应放在哪里 |
| --- | --- | --- |
| 餐饮经营问题开场 | 用户先判断是否与自己痛点相关 | 首页首屏和 Solutions |
| 业务结果承诺 | 从功能介绍转为经营价值表达 | 首页首屏、产品总览 |
| 产品 / 解决方案矩阵 | 帮用户理解餐道能力边界 | 产品总览、Solutions，总页轻量预览 |
| 具体能力和使用场景 | 支撑采购与试用判断 | 产品详情页 |
| 集成和合作生态 | 降低 IT / 数字化负责人风险 | Integrations 独立核心页 |
| 客户 / 数据 / 案例证明 | 建立企业级采购信任 | 首页轻量证明、案例页详细展开 |
| 企业可信背书 | 支撑长期合作和合规判断 | About / Trust |
| 联系方式和下一步转化 | 把不同意图导入正确表单 | Contact / Demo |

## 3. 与 T36 的结合判断

T36 的低密度方向是对的，但还可以从竞品 brief 中补足三点：

| T36 当前方向 | 可补强点 | 补强方式 |
| --- | --- | --- |
| 入口分流型 | 需要更明确地分流到完整页面网络 | 分流入口不仅按角色，也按 `Solutions / Products / Integrations / Contact` 目的地 |
| 叙事引导型 | 可增加真实餐饮场景与经营结果表达 | 首屏用餐饮现场 + 经营问题，不急着展示系统能力 |
| 目录入口型 | 目录清晰但可能偏静态 | 每个目录入口加“用户为什么要点进去”的一句业务收益 |

关键原则：保持首页轻，但让用户清楚知道下一层能解决什么问题。

## 4. 三家竞品可借鉴方式

### 4.1 Deliverect：信息架构优先

适合借鉴：

- 多页面导航和清晰页面族。
- 集成目录的搜索、分类、请求新集成入口。
- 联系页按意图分流。

对餐道的落地方式：

- 官网导航保持 `Solutions / Products / Integrations / Resources / About / Contact`。
- 首页只展示目录入口和少量证明。
- `Integrations` 作为核心页面，而不是首页里的一个小模块。

### 4.2 TabSquare：餐饮场景叙事

适合借鉴：

- 从餐厅现场、顾客体验和增长结果进入。
- 视觉上更有人味，不只展示后台系统。
- 品牌叙事和预约表单之间衔接自然。

对餐道的落地方式：

- 首页首屏优先用“餐饮经营现场 + 统一营运结果”。
- 减少首屏技术术语。
- 在第二屏再解释订单、菜单、点餐、配送、数据如何连接。

### 4.3 Aigens：产品深度验证

适合借鉴：

- 产品详情页有足够深度。
- 能解释复杂系统连接。
- FAQ、案例和功能细节用于降低采购疑虑。

对餐道的落地方式：

- 首页不承载 Aigens 式深内容。
- 产品详情页采用“痛点 -> 定位 -> 收益 -> 功能 -> 工作流 / 数据流 -> 集成 -> 案例 -> FAQ -> CTA”。
- 集成能力可通过“餐道连接层”图示进入详情页，而不是在首页铺满表格。

## 5. 新增方案

### 方案 A：信息架构优先型

参考重点：Deliverect。

适合场景：团队更重视清晰目录、销售转化和后续内容维护。

首页结构：

1. 首屏定位 + 主 CTA。
2. 按需求进入：Solutions / Products / Integrations / Contact。
3. 简化产品概览。
4. 客户 / 集成 / 服务经验三项证明。
5. 分流式联系入口。

优点：最稳，最适合企业官网 MVP。

风险：如果视觉素材不足，可能显得理性但不够有记忆点。

### 方案 B：餐饮场景叙事型

参考重点：TabSquare。

适合场景：希望官网更有餐饮行业温度和品牌感染力。

首页结构：

1. 餐饮现场首屏 + 经营结果承诺。
2. 三个经营问题：订单分散、菜单重复维护、数据难统一。
3. 餐道连接流程：渠道 -> 餐道 -> 门店 -> 数据。
4. 一个客户故事 + 一个集成能力入口。
5. 预约示范 / 查看集成。

优点：更适合对外展示和品牌传播。

风险：需要真实、高质量、可授权的餐饮场景图片，否则容易变成泛泛的餐饮科技视觉。

### 方案 C：产品深度验证型

参考重点：Aigens。

适合场景：目标用户偏 IT、数字化负责人或大型餐饮集团采购评估。

首页结构：

1. 首屏说明餐道是餐饮系统连接与营运数据平台。
2. 简化平台图：订单、菜单、配送、数据、集成。
3. 三个验证入口：产品详情、集成能力、客户案例。
4. 企业可信证明。
5. 联系销售 / 请求集成。

优点：更有企业级可信度。

风险：首页容易重新变重，需要严格限制只显示入口，不展开细节。

### 方案 D：推荐混合型

推荐采用混合方案，而不是单独模仿某一家竞品。

组合方式：

- 首页首屏采用 TabSquare 的餐饮场景叙事。
- 导航和站点结构采用 Deliverect 的信息架构清晰度。
- 产品详情页采用 Aigens 的深度解释方式。
- 集成页采用 Deliverect 的搜索 / 分类 / 请求新集成结构。
- 联系页采用多意图分流。

推荐首页结构：

1. 餐饮场景首屏：一句话定位、经营结果、预约示范、查看集成。
2. 选择你的需求：营运增长、系统集成、产品能力、合作咨询。
3. 平台如何连接：渠道、菜单、配送、数据四步以内。
4. 轻量证明：客户经验、集成生态、服务支持。
5. 分流 CTA：预约示范、联系销售、合作伙伴、客户支持。

这个方案最适合当前阶段，因为它保留 T36 的低密度，同时把竞品 brief 的强项分配到正确页面。
